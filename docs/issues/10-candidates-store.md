# 10 — Candidates store (`candidates.yaml`) and schema

## Title

`src/store/candidates.ts`: machine-owned candidates schema, wholesale rewrite, lookups

## Summary

Implement the machine-owned candidate tier per DESIGN.md §7.3: schema, ordered
wholesale rewrite with generation metadata, and the read/lookup/update surface
used by extract (24), read commands (25), curation (26), and draft (37).

## Context

`candidates.yaml` is the only file `extract` writes; its determinism is the
core testability property of the pipeline. Draft (37) performs the one partial
update allowed: filling `suggestedDefinition`.

## Scope

- Schema + store + unit tests.

## Detailed Requirements

1. Zod schema `CandidatesFile` per §7.3, `.strict()`:
   `schemaVersion: 1`; `generatedBy` string `glossary@<semver>`;
   `generatedAt` ISO datetime (issue 03 format); `candidates: Candidate[]`.
   `Candidate`: `key` (non-empty), `surface`, `surfaces: string[]` (≥1,
   contains `surface`), `kind` enum as in 09, `score` number ≥ 0 (2-decimal),
   `extractors: string[]` (≥1, from the fixed id set `ja-domain|identifiers|
   abbreviations|doc-definitions`), `occurrences` int ≥ 1, `sources:
   {path, line, snippet?}[]` (1–5, snippet ≤ 200 chars), `suggestedDefinition:
   string|null`, `suggestedDefinitionSource: 'doc'|'llm'|null` (null iff
   definition null).
2. `readCandidates(glossaryDir)`:
   - Missing file ⇒ `{file: null, candidates: []}` (extract not yet run — NOT
     an error; commands produce hints).
   - Schema failure ⇒ RuntimeError `E_SCHEMA_INVALID` with file+first issues
     (machine file must not be hand-edited; hint says re-run extract).
3. `writeCandidates(glossaryDir, candidates, meta: {version, clock})`:
   - Sort by (score desc, key asc via compareCodepoint); enforce snippet
     control-char stripping and length caps HERE (last line of defense);
     write with header `# GENERATED by 'glossary extract' — do not edit by hand`.
4. `updateSuggestedDefinitions(glossaryDir, updates: Map<key, {text, source: 'llm'}>)`
   — read, apply to matching keys only (missing keys returned as
   `notFound: string[]`), rewrite preserving order and `generatedAt`
   (draft does not change generation metadata; add
   `draftedAt` NOT — keep file schema unchanged, no extra field).
5. `candidateKeySet(candidates): Set<string>` helper.

## Acceptance Criteria

- [ ] Schema tests incl. surfaces-contains-surface rule, extractor id enum, source count 1–5, suggestedDefinition/source null-pairing.
- [ ] write→read round-trip deep-equal; byte-golden for a 3-candidate JA/EN sample; header comment present; ordering rule enforced (equal scores → key order).
- [ ] Snippet with `` and 500 chars is stripped/truncated on write.
- [ ] updateSuggestedDefinitions: applies to 2 of 3 keys, reports 1 notFound, file remains schema-valid and ordered, generatedAt unchanged.
- [ ] Missing-file read returns empty without throwing.

## Validation

`npm run test` with committed golden.

## Dependencies

04, 08.

## Non-goals

Merge/scoring logic (23), extract orchestration (24), any preservation of
hand edits (unsupported by contract, ADR-002 §2).
