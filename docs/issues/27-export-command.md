# 27 — `glossary export`: deterministic GLOSSARY.md

## Title

`glossary export`: render curated terms into a committed Markdown glossary

## Summary

Implement the Markdown export per DESIGN.md §10.9: deterministic ordering,
kind grouping, Markdown-safe escaping, and the pending-definition marker.

## Context

GLOSSARY.md is the shareable artifact for people who never run the CLI; it
must diff cleanly (stable order) and never break rendering regardless of term
content (hostile fixture).

## Scope

- `src/export/markdown.ts` (pure renderer) + `src/cli/commands/export.ts` +
  tests with goldens.

## Detailed Requirements

1. Input: all curated terms (any `readAllTerms` problem ⇒ RuntimeError
   `E_SCHEMA_INVALID` listing the files; export refuses partial output).
   Every `relatedTerms` id must resolve against the loaded terms — a missing
   id ⇒ RuntimeError `E_BAD_REF` (add to 03's ErrorCodes) listing file + id;
   link text = target's `term`, href = target's heading anchor. Candidates
   NEVER appear.
2. Ordering (DESIGN §10.9): `sortKey = (reading ?? term).normalize('NFKC')`
   (no lowercasing/stripping — NOT normalizeSurface); sort by
   compareCodepoint(sortKey), tie → id. Grouped by kind in fixed order:
   domain, abbreviation, code, doc-defined — each an H2 with fixed titles:
   `## ドメイン用語 / Domain terms`, `## 略語 / Abbreviations`,
   `## コード用語 / Code terms`, `## 文書定義 / Doc-defined terms`
   (bilingual headers; body language is whatever the definitions are).
   Empty groups omitted.
3. Per-term block:
   ```markdown
   ### 支払予約
   よみ: しはらいよやく ｜ 別名: 支払い予約, payment reservation ｜ タグ: `billing`

   請求確定前に支払枠を確保する処理。…

   <sub>出典: [docs/billing.md:12](docs/billing.md#L12) ほか2件 ｜ 関連: [与信枠](#与信枠)</sub>
   ```
   - Meta line omits absent parts entirely.
   - Empty definition ⇒ `_（定義未記入 / definition pending）_`.
   - `definitionSource: llm` ⇒ prepend line `> ⚠️ LLM draft — human review pending`.
   - Sources: link first source as relative path with `#L<line>` anchor, count
     the rest (`ほか N件`); relatedTerms link to in-page anchors of the target
     term heading (GitHub anchor algorithm: lowercase, spaces→-, strip
     punctuation — implement the documented subset and test with JA headings,
     which GitHub keeps verbatim).
4. Escaping — context matrix (ALL store-derived strings are untrusted;
   `escapeMd` = HTML-neutralize `& < >` to entities THEN backslash-escape
   `` \ ` * _ [ ] | `` and line-leading `# > -` ):
   | Context | Rule |
   |---|---|
   | heading text (term) | escapeMd |
   | meta line (reading/aliases/tags) | escapeMd per value |
   | definition/notes paragraphs | escapeMd per line |
   | link TEXT (related term, source path) | escapeMd |
   | link DESTINATION (source path + `#L<line>`) | percent-encode each path segment (`encodeURI`-style, keeping `/`); paths are schema-guaranteed relative (09) — assert no `:` scheme prefix and no leading `/`, else E_BAD_REF-style RuntimeError |
   | heading anchors (related links) | GitHub anchor algorithm over the ESCAPED heading |
   No raw `<`, `>`, or `&` from store data may survive into the output.
5. Header block at top: title (config.site.title), one-line provenance
   `<!-- Generated by glossary vX.Y.Z — do not edit; run 'glossary export' -->`,
   term count. NO timestamp in the body (diff noise); clock unused.
6. Output path: config.export.path (default GLOSSARY.md), resolved under
   repoRoot (escape check E_PATH_ESCAPE), atomic write. `--out <path>`
   overrides (same check).
7. `--json` data: `{path, terms: n}` (issue-06 envelope).
8. Error codes (exit 1 unless noted): `E_SCHEMA_INVALID` (invalid term
   files), `E_BAD_REF` (missing related id / unsafe source path),
   `E_PATH_ESCAPE` (out path, exit 2 as UsageError), write failures
   propagate as RuntimeError.

## Acceptance Criteria

- [ ] Golden test: 5-term curated set (JA/EN mixed, one pending, one llm-flagged, aliases/tags/related) → byte-exact GLOSSARY.md committed as golden.
- [ ] Hostile escaping assertions: output contains no raw `<`, `>`, `<script`, `<img`, `onerror=` originating from store fields; a term of `<img src=x onerror=alert(1)>` appears entity-escaped; a path-like `docs/a b#c].md` source link is percent-encoded and repo-relative; a `javascript:x` prefixed string in a path field triggers the unsafe-path error.
- [ ] Missing relatedTerms id ⇒ exit 1 `E_BAD_REF` naming file and id.
- [ ] Determinism: shuffle input file order ⇒ identical bytes.
- [ ] Reading-based ordering asserted: a term with reading しはらいよやく sorts by the reading, not by its kanji surface (construct a pair that flips order).
- [ ] Empty glossary ⇒ file with header + `_No terms yet_` line, exit 0.

## Validation

Renderer/command-level golden tests over curated-term fixtures built via
store APIs (full pipeline e2e is issue 28). Optional: view the golden on a
GitHub branch preview to confirm anchors — validation aid, not an AC.
